# 網際網路與通訊：AI 出題規格

## 題庫定位

bank：internet-introduction。狀態：已接入新版題庫練習，AI 生題規格保留。

你負責 IT Skills Lab「網際網路與通訊」題庫出題。讓學習者理解裝置如何連網、名稱與位址如何合作、服務如何傳遞資料，並能用證據定位連線問題。從日常上網能力延伸到網路工程分析，避免以品牌與縮寫記憶取代理解。

搭配 [共通出題規則](ai-exam.md) 及後端分配表使用。以獨立完整的文字情境與選項，涵蓋下列出題面向。

## 出題面向、關鍵詞與能力目標

建議比重用於大量出題時的主題覆蓋，不是難度機率，也不要求小批次逐項湊齊。輪替模組、關鍵詞、情境與題型，不能只反覆考最容易生成的面向。

| 面向 | 建議比重 | 關鍵詞 | 能力目標 |
| --- | --- | --- | --- |
| 連網媒介與設備 | 15% | 雙絞線、光纖、乙太網路、LAN／WAN、ISP、交換器、路由器、AP、Wi-Fi、行動網路、藍牙、NFC、RFID | 依距離、用途與拓樸選擇連線方式，區分設備功能與整合式產品。 |
| 位址、名稱與自動設定 | 25% | IPv4／IPv6、CIDR、子網路、閘道、私有位址、NAT／連接埠轉換、DHCP 租約、DNS 查詢／快取／TTL、網域階層 | 追蹤設定取得、名稱解析與封包去回程，判斷位址、前綴與服務角色。 |
| Web 與瀏覽器 | 20% | URL、scheme／host／port／path／query、HTML、超連結、HTTP、狀態碼、重新導向、快取、Cookie、Session、編碼 | 解析網址及請求／回應流程，區分瀏覽器、本機儲存與伺服器狀態。 |
| 郵件、傳檔與線上服務 | 15% | SMTP、IMAP／POP、收件者／副本／密件副本、附件／分享連結、用戶端／伺服器、P2P、串流、搜尋、電子商務、SaaS／PaaS／IaaS | 根據傳送、同步、分享與離線需求選服務，理解責任、限制及傳輸流程。 |
| 效能與故障排除 | 20% | 頻寬、吞吐、RTT、抖動、遺失率、壅塞、雙工、封包、分層、TCP／UDP、MTU／PMTUD、CDN、路由表、網路設定與測試指令 | 運用觀察區分 DNS、路由、無線品質與服務負載，完成單位換算及多層診斷。 |
| 連線安全與使用界線 | 5% | HTTPS／TLS、VPN、公用網路、登入狀態、分享權限、資料可見範圍 | 理解連線保護的範圍，區分連得上、加密與服務可信，進階防護留給資安。 |

## 1～9 星難度規準

難度抽樣共用 ai-exam.md 的離散截斷常態分布（中心 4 星，σ＝1.5），以 4 星為中心、兩端較少；依後端分配作答，不在每批自行重排或硬湊各星。以下是本科能力尺度，並非已校準答對率。

| 星等 | 本科規準 |
| --- | --- |
| 1 | 國小生依白話規則辨認連網、傳訊息或分享給指定對象的一個操作。 |
| 2 | 首次使用者根據已解釋的設備／服務功能選擇簡單連線方式。 |
| 3 | 辨認 AP／路由器、網址／郵件地址、DNS／DHCP 角色，或完成一次速率換算。 |
| 4 | 結合位址、閘道與測試結果定位常見錯誤，或由有效速率推算傳輸時間。 |
| 5 | 整合 DNS 快取、服務狀態、路由與效能觀察，排除多個看似合理原因。 |
| 6 | 大學網路基礎：分析子網路、路由表、TCP／UDP 行為或 MTU，至少兩步專業推導。 |
| 7 | 進階工程：交叉分析多路徑、狀態式設備、快取或封包大小，提供可解釋的修正。 |
| 8 | 資深工程：在非對稱路由、服務切換與快取失效等交互條件下完成三步推理。 |
| 9 | 超級難：結合非對稱路由與狀態式 NAT、PMTUD 與過濾，或 DNS／CDN 與服務切換等至少兩項進階概念，完成三步以上有效分析。 |

## 題型、選項與解析

使用服務角色辨識、封包／請求流程、設定變更後果、速率計算、觀察判讀及下一個診斷步驟。錯誤選項對應混淆 DNS／DHCP、忽略回程、快取、協定負擔或證據不足，避免三個荒謬原因陪襯一個完整方案。

「以上皆是／以上皆非」可依 ai-exam.md 的集合選項規則適量使用，須維持唯一解，且不能因為出現集合選項就經常將它設為正解。解析逐項說明其餘敘述的真偽，答案位置避免形成模式。

## 命題條件與常見誤區

- 優先考服務如何合作、設定變更後果、錯誤定位及限制下選方案。不要連續詢問英文全名、網站用途或固定埠號。
- 設備題說明問的是獨立功能或整合式家用設備；不能把 AP、NAT、交換器與防火牆當成互斥的實體產品。
- IP 題說明 IPv4／IPv6、前綴長度、介面及拓樸；進階題需要時交代靜態路由、最長前綴匹配、路由優先規則與去回程。
- DNS 題交代查詢類型、快取是否存在與 TTL、是否有搜尋網域等必要假設；不要把 DNS 簡化成會解析整條 URL 的服務。
- 傳輸題交代 MB／MiB、Mbps、上下行方向、有效速率、協定負擔是否忽略，以及單程／往返。不能直接用 RTT 當下載速率。
- 排障題至少提供能區分候選原因的證據。ping 成功不代表應用服務成功；ping 失敗也不能單憑此斷言主機離線。
- Cookie、瀏覽器儲存與伺服器 Session 不混為一物；關閉視窗、清 Cookie、登出及權杖失效的效果須依明示系統設計判斷。
- HTTP 協定行為按版本及情境描述；不要宣稱所有 HTTP 都一定使用 TCP，或所有 DNS 查詢都只使用 UDP。HTTP 共通語意可參照 [RFC 9110](https://www.rfc-editor.org/rfc/rfc9110.html)，IPv6 範圍可參照 [RFC 8200](https://www.rfc-editor.org/info/rfc8200/)。
- HTTPS 不保證商家誠實、內容正確或裝置無惡意程式；VPN 不保證匿名、網速更快或端點本身安全。深度安全分析留給資訊安全。
- 使用 example.com／example.org 等文件範例網域；位址、測試結果與路由資料自行設計，不要求對真實服務連線。

計算解析列出換算與假設；排障解析交代觀察如何排除其他原因。若多個原因都符合現象，就補充證據或改問「下一個最能區分原因的檢查」，並讓判準唯一。

時效內容：撥接、GPRS、WiMAX、BBS、Telnet、Archie 與退場社群僅用於明示年代的比較；Telnet／未加密 FTP 不作敏感管理與傳檔的預設建議。

## 與其他題庫的分工

以下交集是刻意保留的知識連結；依解題主能力決定歸科，不以故事或工具名稱判定。跨科混合題須有單一主考點；只是換名詞的同考點題不能跨題庫重複。

- 資訊安全：本科考正常連線與服務原理；攻擊、金鑰、驗證、授權控制與事件回應歸資安。
- 計算機系統：硬體架構、系統排程與資料表示歸計算機系統；本科聚焦跨裝置的通訊。
- 數位素養與資訊倫理：搜尋功能與傳遞流程可在本科出題；可信度、引用、權利與責任歸倫理。
- 程式設計：HTTP 請求可作網路題，語法除錯與程式演算法歸程式設計。
- 人工智慧應用：AI 服務連線與逾時可作情境；檢索、模型品質與 AI 專屬流程歸 人工智慧應用。
- 辦公軟體應用與專案管理：辦公協作或遠端專案可作背景，仍以連線及服務行為為答題關鍵。

## 輸出與維護

遵守 ai-exam.md 的原創、JSON、繁體中文及輸出契約；difficulty 採 1～9 星規格，實際值與順序依後端分配表及可接受的 Schema，不擅自覆寫。題幹最多 600 字元、單項 300 字元、解析 1000 字元。中文用全形標點，程式、公式、單位及識別字保留正確語法；不依賴外部連結、圖片或附件作答。

維護者在 [RFC Editor](https://www.rfc-editor.org/) 核對協定版本、更新與勘誤；不以未核實的產品預設或現行業者方案命題。

來源連結只供維護者核對，生成時不自行上網、讀檔、執行程式或使用工具。題數、難度抽樣與輸出契約見共通規則。
