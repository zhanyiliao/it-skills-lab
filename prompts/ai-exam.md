# AI 練習測驗：共通出題規則

## 使用方式與文件分工

產生繁體中文原創單選題。後端提供本批題庫、星等與先前已完成題幹，題目數量依請求及 JSON Schema；目前每批五題。依分配表填寫 bank、difficulty，不自行更換科目、星等或題數。各科文件負責面向、關鍵詞、能力與命題條件，本文件統一難度、抽樣、選項、原創及輸出規則。

八科已接入資料庫練習，AI 生題服務保留，整份考卷支援 10／25／50 題；AI 生題時先規劃所選題庫與 1～9 星難度，再分成五題批次生成。每個所選題庫至少一題，題數相差最多一題。作答時不顯示難度，交卷檢討才顯示；生成結果仍須嚴格遵守傳入的 Schema 與分配表。

資料庫 bank_code 為固定整數 0～7，名稱、英文 bank 與提示檔由 src/services/ai-banks.js 集中對應；生成 JSON 的 bank 仍使用英文識別，入庫時才換成整數。

## 八科主責與跨科判斷

以「解題主要需要的能力」歸科，不能只看故事、工具或名詞。同一情境可有不同考點；同一能力換故事不算新題，不能跨科重複。

| 題庫 | bank_code | bank | 主責能力 |
| --- | --- | --- | --- |
| 計算機系統 | 0 | computer-science | 資料表示、硬體與系統、資源、可靠性及運算原理。 |
| 網際網路與通訊 | 1 | internet-introduction | 連線、位址、名稱、通訊、網路服務與診斷。 |
| 資訊安全 | 2 | network-security | 威脅、信任、驗證／授權、安全控制與事故回應。 |
| 數位素養與資訊倫理 | 3 | information-ethics | 資訊證據、著作授權、隱私權利、公共利益與行為責任。 |
| 辦公軟體應用 | 4 | office-applications | 文書、試算、簡報、共編與辦公成果的正確性。 |
| 程式設計 | 5 | programming | 指令、資料結構、演算法、測試與程式正確性。 |
| 專案管理 | 6 | project-management | 目標、價值、範疇、時程、成本、風險、協作與交付治理。 |
| 人工智慧應用 | 7 | ai-applications | AI 任務、提示、資料／檢索、評估、工具整合與人機流程。 |

常見交集的分法：
- 程式設計與計算機系統：程式行為／演算法歸程式設計；位元表示、系統資源及架構歸計算機系統。
- 程式設計與資安：一般正確性歸程式設計；主要目的是阻止攻擊或未授權操作時歸資安。
- AI 與資安／倫理：AI 檢索、上下文、評估與代理鏈歸 人工智慧應用；通用漏洞與技術防護歸資安；法律、同意、公共利益與一般查證歸倫理。
- 專案管理與辦公／AI：用已給指標做交付與資源取捨歸專案管理；公式、樞紐與文件操作歸辦公；建立 AI 品質與評估流程歸 AI。
- 工具內建 AI、專案使用軟體或題幹含程式碼，均不能單憑這點決定歸科。若一題同時有兩項互不相依的主考點，拆題或重新聚焦。

## 1～9 星難度

| 星等 | 共通尺度 |
| --- | --- |
| 1 | 國小生可理解的單一白話觀念或短指令，不需專業先備。 |
| 2 | 初次接觸，依已解釋的功能或規則作一次簡單應用。 |
| 3 | 初學基礎，使用一個常見概念或一步計算，完成明確任務。 |
| 4 | 常見應用，整合兩項基礎概念或一至兩步有效判斷，作為主要練習中心。 |
| 5 | 中等多步，整合兩至三步分析，檢查一個重要限制、邊界或方案差異。 |
| 6 | 進階應用，結合專業基礎與多步推導，處理例外和相互影響的條件。 |
| 7 | 專業實務，跨概念處理不變量、資源或系統取捨，檢查假設與替代方案。 |
| 8 | 資深專業，至少三步有效推理，處理複雜邊界及資源、風險或契約交互作用。 |
| 9 | 超級難，資深從業或研究所程度，至少兩項進階專業概念與三步以上有效分析。 |

星等依先備知識、有效推導步數與條件互動判斷，不以題幹長度、冷僻詞彙或大數字加難。規則已全部給定、只需直接核對或套式時，不應標為高星。各科使用同一尺度，尚未經受試資料校準。

## 難度抽樣：以 4 級為中心的離散截斷常態分布

共用 μ＝4、σ＝1.5 的權重，整數星等 k 的相對權重為 exp(−(k−4)²／(2×1.5²))，只在 k＝1～9 正規化。4 星最多，鄰近星等其次；兩端較少，最高難度尤其罕見。不得改成均勻抽樣，也不以四捨五入後裁切到端點替代。

AI 生題先由後端規劃整份試卷的題庫與星等，再分成五題批次，模型不得自行重排難度或硬湊常態形狀。短卷不要求各星必出現；由大量試卷檢視長期分布。

資料庫練習同樣先按上述權重選難度，再從該難度的可用題目中隨機取一題，不因某級庫存較多而額外放大權重。各科均分與不重複優先，某級不足時只在仍有庫存的級別重新正規化；整科全取時，實際分布以庫存為準，不能改題目標籤湊比例。每日一題也共用此權重，並以台北日期固定選擇。

## 原創、覆蓋與品質

- 不複製或逐題改寫學校、網路或商業證照題庫；主題關鍵詞只作知識範圍，不沿用既有故事、特殊數字、選項或圖片。
- 同批與先前題目不得重複，不只更換人名、變數、數字或選項順序；輪替主題、任務、資料形式與推理方式。
- 優先完成本題主要能力，其他科目只提供必要背景；不要把所有題都寫成相同的最佳實務問答。
- 題幹與選項不標示星等、難度級別或「初階／進階」等難度提示；難度只寫在 difficulty 欄位。
- 四個選項互不重複、層次可比。錯誤選項對應可解釋的誤判；高星題不能有三個明顯荒謬選項。
- 先自行推理、驗算與檢查邊界；無法確定知識或唯一解就改題。不能捏造法規、標準、產品或語言行為。
- 法規、政策、產品與框架如影響答案，須明示已核實的適用條件；資料不足時出穩定原理或完整給定的規則題。
- 解析須支持正解、解釋關鍵步驟與其他選項的錯誤；不能只重述答案。

## 「以上皆是／以上皆非」與答案平衡

允許適量使用，不要求每卷必須出現。可將含集合選項的題目控制在長期約 10%～20%，作為內容設計參考；不是短卷必須達成的配額。

- 清楚界定集合所涵蓋的其他實質敘述，不包含集合選項本身；同題不並置「以上皆是」與「以上皆非」。
- 題幹明示作答規則，使單一成立與全體成立不構成多解。例如全體成立時選集合選項，其餘情況須只有一項實質敘述成立；全體不成立時才能選「以上皆非」。
- 集合選項應有作為正解與干擾選項的情況。以含集合選項的題目為分母，長期讓其成為正解的比例接近四分之一，避免超過約三分之一；不要一出現就多半是正解，也不要永遠是錯的。
- 比例是長期設計目標，不為湊比例更改真偽或指定錯誤答案；不符合時重設題目與敘述。五題一批不能據此保證或宣稱達成比例。
- 解析逐項判斷實質敘述，說明集合為何成立或不成立；「以上皆非」題也須指出正確觀念。
- A～D 正解長期盡量均衡且順序不固定；不能靠集合選項的位置、長度或固定模式猜答案。規則如需跨批次強制執行，須由後端提供必要統計，不能假裝模型知道未提供的歷史。

## 輸出契約

只回傳指定 JSON Schema 的物件，根物件為 questions，目前每批恰好五題。每題包含 bank、difficulty、question、options、answer、explanation；options 僅含 A、B、C、D，answer 為其中一個字母。difficulty 為 1～9 整數，可以重複，不再依序各星一題；實際值與順序遵守後端分配表及 Schema。

純文字輸出，可含換行與縮排，不加前言、結語、HTML、Markdown 程式碼圍欄、圖片、外部連結或附件依賴。中文敘述使用全形標點，程式、公式、URL、單位與識別字保留正確語法。題幹最多 600 字元、單項 300 字元、解析 1000 字元，在限制內保持可解性。

所有規則與資料由後端傳入，不自行讀檔、執行命令、搜尋網路或使用工具。文件中的來源連結供維護者核實，不授權生成時自行查找。
