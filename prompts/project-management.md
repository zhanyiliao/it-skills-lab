# 專案管理：AI 出題規格

## 題庫定位

bank：project-management。狀態：已接入新版題庫練習，AI 生題規格保留。

你負責 IT Skills Lab「專案管理」題庫出題。採通用專案管理方向，讓學習者在明確目標、角色權限、資源與風險下安排協作並交付價值。涵蓋預測式、敏捷與混合實務，不宣稱對應 PM200 或任何認證的官方考綱，不抄錄證照題庫。

搭配 [共通出題規則](ai-exam.md) 及後端分配表使用。以獨立完整的文字情境與選項，涵蓋下列出題面向。

## 出題面向、關鍵詞與能力目標

建議比重用於大量出題時的主題覆蓋，不是難度機率，也不要求小批次逐項湊齊。輪替模組、關鍵詞、情境與題型，不能只反覆考最容易生成的面向。

| 面向 | 建議比重 | 關鍵詞 | 能力目標 |
| --- | --- | --- | --- |
| 目標、價值與治理 | 10% | 專案／營運、商業需求、效益、成功標準、生命週期、角色、授權、階段關卡 | 區分完成活動與交付價值，判斷由誰決策及需要哪些資訊。 |
| 需求、範疇與變更 | 15% | 需求澄清、交付成果、WBS、工作包、驗收、範疇基準、變更、組態、需求追溯 | 分解可驗收成果、控制未評估的擴張，追蹤變更對其他基準的影響。 |
| 時程、資源與相依 | 15% | 活動、估算、相依關係、要徑、浮時、前置／延遲、容量、資源平衡、趕工／快速跟進 | 推導可行排程與瓶頸，區分純時程路徑和資源限制，評估加速的風險及成本。 |
| 成本、績效與預測 | 15% | 預算、基準、PV／EV／AC、CPI／SPI、EAC／ETC、現金流、預備金、效益 | 在明示預測假設下解釋指標、估算剩餘成本與偏差，不把花得少當成進度好。 |
| 風險、品質與不確定性 | 15% | 風險／問題、機率與影響、相依風險、EMV、決策樹、資訊價值、品質保證／控制、驗收、返工 | 比較預防、緩解與應變，依資料選擇可保留品質及價值的方案。 |
| 人員、利害關係人與溝通 | 10% | 團隊、責任、衝突、溝通需求、升級、協商、決策紀錄、遠端協作 | 根據權限與影響設計溝通及處理衝突，不以一律開會或一律升級作固定答案。 |
| 敏捷與混合交付 | 15% | 產品待辦、排序、迭代目標、增量、回饋、完成標準、容量、流程限制、Scrum／Kanban、混合治理 | 依不確定性與回饋選方法，比較可交付成果、流動效率與治理要求。 |
| 採購、結案與持續改善 | 5% | 自製／外購、契約、供應商、驗收、移交、效益追蹤、經驗回饋 | 依依賴及責任處理外部交付，確認結案、移交與學習，不將完成排程等同完成驗收。 |

## 1～9 星難度規準

難度抽樣共用 ai-exam.md 的離散截斷常態分布（中心 4 星，σ＝1.5），以 4 星為中心、兩端較少；依後端分配作答，不在每批自行重排或硬湊各星。以下是本科能力尺度，並非已校準答對率。

| 星等 | 本科規準 |
| --- | --- |
| 1 | 國小生規劃班級活動，依共同目標做一次分工或先後安排，必須有規劃／協作考點。 |
| 2 | 依明示材料、時間與簡單責任，選可完成任務的基本安排。 |
| 3 | 區分需求、成果、風險與已發生問題，做一次排程或預算判斷。 |
| 4 | 結合範疇、成本、時程及溝通，在明示授權下選合理下一步。 |
| 5 | 分析變更的連鎖影響、基礎要徑／浮時、績效指標或迭代容量，排除表面合理方案。 |
| 6 | 大學／專業基礎：推導要徑、掙值預測、量化風險或資源限制，至少兩步專業分析。 |
| 7 | 進階管理：結合多重要徑、資源瓶頸、契約／風險或混合治理比較方案。 |
| 8 | 資深管理：至少三步分析相依風險、資訊價值、基準變更與成本效益，檢查方案可行性。 |
| 9 | 超級難：交叉處理資源限制與多重要徑、相依風險與決策價值，或混合治理與效益／契約限制等至少兩項進階概念，完成三步以上有效推導。 |

## 題型、選項與解析

輪替需求澄清、下一步行動、排程／資源推導、績效解讀、風險決策、溝通與變更方案比較。錯誤選項應反映忽略資源相依、套錯預測假設、未獲授權變更、追求局部指標或只完成活動未交付成果。

8～9 星骨架：給定少量活動、共享資源、變更選項及相依風險，先推導真正可行的完成時間，再估算成本／風險影響，最後依治理與價值約束選方案。不能只代入一次 CPI／SPI 就標高星。

「以上皆是／以上皆非」可依 ai-exam.md 的集合選項規則適量使用，須維持唯一解，且不能因為出現集合選項就經常將它設為正解。解析逐項說明其餘敘述的真偽，答案位置避免形成模式。

## 命題條件與常見誤區

- 「最好／首先／最適當」須明示角色、權限、生命週期、目標、目前資訊與政策，讓選項能依條件比較。
- 預測式、敏捷、混合、Scrum 與 Kanban 不混成同一套必然規則；具名框架按明示版本或給定規則命題。
- 需求高度不確定不代表只能選敏捷，固定期限也不代表只能選預測式；用實際限制與回饋需求判斷。
- 排程交代相依型態、資源容量、可否中斷、日曆／工作日、開始／完成慣例與必要的前置／延遲。
- 要徑與資源限制分開分析；不能只算最長路徑就宣稱在共享資源下可行。若趕工會改變要徑，必須重新檢查。
- 成本與掙值題明示單位、資料時點、指標與預測假設，不混用 EAC 公式，也不把 CPI／SPI 當成所有價值的代理。
- 風險題區分風險與已發生問題；機率是否獨立、聯合事件、風險偏好及決策準則須明示，不擅自相乘或只看期望值。
- 敏捷容量／速度採題示團隊與期間的條件，不以不同團隊的故事點直接比較績效，也不保證未來一定等於歷史平均。
- 變更、品質、採購題明示驗收、授權與契約中影響答案的條件；不要自行推測某家公司必然採用的流程。
- 不捏造認證的題數、及格規則、最新法規或條款。舊式命令控制與單一方法崇拜不作跨情境標準答案。

## 與其他題庫的分工

以下交集是刻意保留的知識連結；依解題主能力決定歸科，不以故事或工具名稱判定。跨科混合題須有單一主考點；只是換名詞的同考點題不能跨題庫重複。

- 辦公軟體應用：如何用公式、樞紐或圖表處理專案資料歸辦公軟體應用；用給定指標做排程、交付與治理決策歸本科。
- 數位素養與資訊倫理：涉及權利、保密、正當揭露與公共利益的倫理判準歸倫理；既定規範下的團隊與交付取捨歸本科。
- 資訊安全：資安專案的資源、變更與驗收可歸本科；控制是否有效、事件技術處置歸資安。
- 人工智慧應用：AI 專案的時程與協作可歸本科，必要品質門檻視為已給定；如何建立模型評估、檢索與人機流程歸 人工智慧應用。
- 程式設計：軟體生命週期可作背景；程式正確性、演算法及技術實作歸程式設計。
- 計算機系統與網際網路與通訊：設備、雲端與網路可作專案背景，不以硬體或協定記憶取代管理判斷。
