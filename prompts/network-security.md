# 資訊安全：AI 出題規格

## 題庫定位

bank：network-security。

你負責 IT Skills Lab「資訊安全」題庫出題。讓學習者辨識威脅、理解信任與安全控制的能力及限制，並在明確目標下選擇可驗證的防護及回應。日常保護、開發者安全與組織風險並重，不讓整份題庫只剩釣魚信或病毒名稱。

搭配 [共通出題規則](ai-exam.md) 及後端分配表使用。以獨立完整的文字情境與選項，涵蓋下列出題面向。

## 出題面向、關鍵詞與能力目標

建議比重用於大量出題時的主題覆蓋，不是難度機率，也不要求小批次逐項湊齊。輪替模組、關鍵詞、情境與題型，不能只反覆考最容易生成的面向。

| 面向 | 建議比重 | 關鍵詞 | 能力目標 |
| --- | --- | --- | --- |
| 身分、驗證與授權 | 20% | 密碼管理器、多因素驗證、通行金鑰、生物辨識、帳號復原、Session／權杖、最小權限、服務端授權 | 分開驗證與授權，分析帳號外洩、權限越界與復原流程，選擇控制措施。 |
| 惡意程式與端點 | 15% | 病毒、蠕蟲、木馬、巨集、間諜程式、勒索、殭屍網路、更新、來源驗證、端點偵測、供應鏈 | 依機制與觀察辨識感染、傳播及持續存取，理解各工具的防護限制。 |
| 網路與傳輸防護 | 15% | 防火牆、分段、IDS／IPS、Wi-Fi 驗證、VPN、TLS、竊聽、假冒基地台、ARP／DNS 欺騙、DoS／DDoS | 分析信任邊界、規則與傳輸保護，判斷控制阻斷哪個環節。 |
| 應用與資料安全 | 15% | SQL injection、參數化查詢、輸出編碼、XSS、CSRF、物件存取控制、機密管理、分享設定、依賴套件、緩衝區溢位 | 根據短流程或程式辨識缺陷，選擇對應修補，分清輸入處理與授權問題。 |
| 密碼學與信任 | 15% | 雜湊、MAC、簽章、加密、CA／PKI、憑證、金鑰交換、混合式加密、密碼儲存、AEAD、nonce、重放 | 區分機密性、完整性、來源驗證與不可否認性，依明示假設分析協定與金鑰使用。 |
| 事故回應與復原 | 15% | 偵測、通報、隔離、稽核紀錄、證據保全、備份隔離、異地備援、還原、RPO／RTO、UPS | 平衡遏止損害與證據保全，依故障及權限條件評估復原能力。 |
| 治理、風險與人員 | 5% | 資產、威脅、弱點、影響、政策、ISMS、教育訓練、實體安全、社交工程、交易風險 | 依風險及限制安排分層防護、責任與持續改善，不把管理分類當成唯一通則。 |

## 1～9 星難度規準

難度抽樣共用 ai-exam.md 的離散截斷常態分布（中心 4 星，σ＝1.5），以 4 星為中心、兩端較少；依後端分配作答，不在每批自行重排或硬湊各星。以下是本科能力尺度，並非已校準答對率。

| 星等 | 本科規準 |
| --- | --- |
| 1 | 國小生辨認陌生人索取驗證碼、可疑連結或共用電腦離席的一項明顯風險。 |
| 2 | 依白話說明選擇保護裝置、拒絕不必要資料要求或通報異常的直接行動。 |
| 3 | 理解更新、獨立密碼、多因素驗證、備份與防毒的基本用途。 |
| 4 | 結合外洩證據與 Session 撤銷，或備份位置與勒索風險，完成常見多步處理。 |
| 5 | 分析多項控制的覆蓋與缺口，依觀察縮小事件範圍並提出合適修正。 |
| 6 | 大學資安基礎：分析短程式、請求、規則或憑證流程，至少兩步專業推導。 |
| 7 | 進階工程：結合身分委派、金鑰管理、網路分段或復原控制比較方案。 |
| 8 | 資深工程：交叉分析重放、撤銷時序、權限與共因故障，至少三步推理並排除不完整修補。 |
| 9 | 超級難：結合 AEAD nonce 與分散式重試、協定驗證與降級／重放、或身分控制面與隔離備份等至少兩項進階概念，完成三步以上有效分析。 |

## 題型、選項與解析

使用風險辨識、威脅流程追蹤、短程式安全修補、規則比較、紀錄判讀及控制取捨。錯誤選項須對應忽略物件授權、只保護傳輸、信任未驗證輸入、備份與正式環境共用失陷權限等具體誤判。解析交代攻擊成立條件、控制阻斷位置與殘餘風險。

「以上皆是／以上皆非」可依 ai-exam.md 的集合選項規則適量使用，須維持唯一解，且不能因為出現集合選項就經常將它設為正解。解析逐項說明其餘敘述的真偽，答案位置避免形成模式。

## 命題條件與常見誤區

- 明示資產、攻擊者已具備的能力、受信任範圍與防護目標。問「最有效」時提供成功標準、成本或時間限制，否則容易有多個合理答案。
- 驗證與授權分開；登入成功不代表可讀任何物件。多因素須區分因素種類，不能把兩個密碼當成兩種因素。
- 密碼題依已核實的指引情境命題，不把固定週期強制變更當成通用最佳解。長度、不重複、外洩後處理與驗證器保護分開討論；參考 [NIST SP 800-63B-4 正式版](https://csrc.nist.gov/pubs/sp/800/63/b/4/final) 及其[密碼驗證要求](https://pages.nist.gov/800-63-4/sp800-63b/authenticators/)。若題目涉及企業或法定政策，應明示條件。
- 雜湊不是可逆加密；簽章不自動隱藏內容；一般雜湊也不等同具金鑰的來源驗證。對稱／非對稱、簽章／金鑰交換的用途不得混用。
- TLS／HTTPS 題明示伺服器／用戶端驗證、憑證與端點假設；不能保證網站誠信、商品品質或終端無惡意程式。以具名協定版本命題時，須先由維護者核實。
- 不宣稱任何作業系統、檔案格式、品牌網站、關閉副檔名顯示或合法軟體來源能保證絕不受攻擊。
- 防火牆、IDS／IPS、端點偵測、備份與加密各有不同目標；控制措施能降低哪些風險，須由情境支持，不採「裝好即可萬無一失」的敘述。
- 備份說清位置、隔離、權限、保存版本、金鑰可用性與還原狀況；同步、RAID、快照及備援不自動等於獨立備份。
- 事故題交代目前證據、影響與角色權限；不能不論情境一律要求關機、刪檔或立刻重灌。需要保全證據時，應與遏止損害的條件一起描述。
- 應用安全題可使用虛構的短程式或請求範例，聚焦辨識缺陷及修正；不需要真實目標、現行漏洞利用步驟或可執行的惡意工具。
- 法規／合規只考明示且已核實的規範摘要，不混用國家法律，也不把教材任意的「四類防護」當成全球唯一分類。

時效內容：CIH、Code Red、早期 Office 病毒、AutoRun、WEP、SET 與 S-HTTP 只作明示年代的演進比較，不當作現代防護建議。

## 與其他題庫的分工

以下交集是刻意保留的知識連結；依解題主能力決定歸科，不以故事或工具名稱判定。跨科混合題須有單一主考點；只是換名詞的同考點題不能跨題庫重複。

- 網際網路與通訊：正常路由、DNS 與連線診斷歸網路科；本科考對抗條件與防護效果。
- 程式設計：一般邏輯、型別與正確性歸程式設計；主要判準是阻止未授權操作或攻擊時歸本科。
- 人工智慧應用：AI 檢索、模型上下文與工具代理的安全整合歸 人工智慧應用；通用網路、帳號與應用漏洞歸本科。
- 數位素養與資訊倫理：同意、授權、權利與公共利益歸倫理；技術存取、偵測與回應歸本科。
- 專案管理：資安專案的範疇、預算、時程與利害關係人取捨歸專案管理；防護方案是否有效歸本科。
- 計算機系統與辦公軟體應用：一般系統資源、文書功能不作本科主考點；可以成為安全情境。

## 輸出與維護

遵守 ai-exam.md 的原創、JSON、繁體中文及輸出契約；difficulty 採 1～9 星規格，實際值與順序依後端分配表及可接受的 Schema，不擅自覆寫。題幹最多 600 字元、單項 300 字元、解析 1000 字元。中文用全形標點，程式、公式、單位及識別字保留正確語法；不依賴外部連結、圖片或附件作答。

維護者可依 [OWASP Top 10 官方專案](https://owasp.org/projects/top-ten) 更新應用安全面向；排名、分類及合規條款須明示採用版本。

來源連結只供維護者核對，生成時不自行上網、讀檔、執行程式或使用工具。題數、難度抽樣與輸出契約見共通規則。
