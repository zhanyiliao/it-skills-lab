# 程式設計：AI 出題規格

## 題庫定位

bank：programming。

你負責 IT Skills Lab「程式設計」題庫出題。讓學習者理解如何將需求轉成可執行的步驟，追蹤程式行為、選擇資料結構與演算法，並以測試、反例和推理驗證正確性。1 星仍須與指令或程式邏輯直接相關，不能退成無關的生活常識或純心算。

搭配 [共通出題規則](ai-exam.md) 及後端分配表使用。以獨立完整的文字情境與選項，涵蓋下列出題面向。

## 出題面向、關鍵詞與能力目標

建議比重用於大量出題時的主題覆蓋，不是難度機率，也不要求小批次逐項湊齊。輪替模組、關鍵詞、情境與題型，不能只反覆考最容易生成的面向。

| 面向 | 建議比重 | 關鍵詞 | 能力目標 |
| --- | --- | --- | --- |
| 指令、狀態與控制流程 | 15% | 順序、輸入／輸出、變數、指定、運算、布林值、條件、短路、迴圈、積木指令 | 追蹤初始狀態與指令後果，理解選擇與重複，找出終止與邊界問題。 |
| 資料、函式與抽象 | 15% | 數值／字串、型別、索引、切片、作用域、參數、回傳、可變性、別名、遞迴、介面契約 | 根據語意推導資料如何傳遞及改變，分清物件共享與複製，建立合理抽象。 |
| 資料結構 | 15% | 陣列、串列、堆疊、佇列、雜湊、集合、樹、堆積、圖 | 依操作需求、順序、查找與更新特性選結構，分析不變量及邊界。 |
| 演算法與複雜度 | 20% | 搜尋、排序、分治、貪婪、動態規劃、走訪、遞迴關係、最壞／平均／攤銷分析 | 比較演算法、辨識反例、推導成本及正確性，明確定義輸入與成本模型。 |
| 除錯、測試與正確性 | 15% | 語法／執行／邏輯錯誤、off-by-one、測試案例、邊界、反例、不變量、前後條件、例外 | 依症狀定位錯誤、選有鑑別力的測試或最小修正，驗證修正沒有破壞其他條件。 |
| 程式組織與資料流程 | 10% | 模組、依賴、責任分離、API 契約、解析／序列化、資源生命週期、錯誤傳遞 | 比較結構與介面，在明示需求下處理失敗與資源釋放，不考框架冷門預設。 |
| 非同步、並行與程式語意 | 10% | 事件、非同步、競態、鎖、原子性、死鎖、線性化、記憶體模型、回收、型別／所有權 | 推導允許的執行結果，判斷同步與生命週期是否足以保證程式正確。 |

## 1～9 星難度規準

難度抽樣共用 ai-exam.md 的離散截斷常態分布（中心 4 星，σ＝1.5），以 4 星為中心、兩端較少；依後端分配作答，不在每批自行重排或硬湊各星。以下是本科能力尺度，並非已校準答對率。

| 星等 | 本科規準 |
| --- | --- |
| 1 | 國小生依機器人或積木的兩三條白話指令追蹤順序或一次選擇，無需語法先備。 |
| 2 | 依已解釋的暫存值或固定次數重複追蹤短指令，不用巢狀流程。 |
| 3 | 初學者追蹤變數、單一分支、短單層迴圈或一次函式呼叫。 |
| 4 | 多步追蹤函式、集合或簡單遞迴，選出有效測試、反例或正確修補。 |
| 5 | 比較基本演算法與資料結構，分析不變量、例外路徑及時間／空間成本。 |
| 6 | 大學專業基礎：推導遞迴關係、正確性或複雜度，至少兩步有效專業分析。 |
| 7 | 進階工程：結合資料結構與攤銷分析，或非同步、共享狀態與資源生命週期。 |
| 8 | 資深工程：分析線性化、記憶體模型、回收或型別契約的交互影響，至少三步推理。 |
| 9 | 超級難：至少兩項進階概念交叉推導，例如弱記憶體模型與安全回收、線性化與 ABA、或型別語意與正確性證明，至少三步有效分析。 |

## 題型、選項與解析

輪替短程式追蹤、程式片段選擇、最小反例、測試設計、除錯修補、資料結構取捨與正確性／成本推導。錯誤選項對應索引差一、錯把指定當比較、忽略別名、漏終止條件、錯判平均成本或誤以為單一原子操作足以保護整個不變量。

8～9 星骨架：明示並行操作與記憶體／回收規則，先推導可發生的交錯，再判斷線性化或存活性，最後比較修補與資源限制。解析必須提供推導，不能只報演算法或鎖的名稱。

「以上皆是／以上皆非」可依 ai-exam.md 的集合選項規則適量使用，須維持唯一解，且不能因為出現集合選項就經常將它設為正解。解析逐項說明其餘敘述的真偽，答案位置避免形成模式。

## 命題條件與常見誤區

- 1～2 星使用白話規則或已解釋的中文偽程式碼；1 星不使用遞迴、指標、位元操作、巢狀迴圈或複雜語法。
- 預設語意明確的偽程式碼；真實程式須標明語言及會影響結果的版本、執行環境與必要規則，不混用語言慣例。
- 明示索引起點、參數傳遞、可變性、整數除法、溢位、求值順序、排序穩定性與例外處理中會影響答案的條件。
- 不把未定義行為當成確定輸出，也不以實作細節或未給定的雜湊／集合走訪順序形成正解。
- 並行題交代原子性、排程限制、同步與記憶體模型；若多種輸出皆可能，題幹明示問可能／不可能或保證成立的性質。
- 複雜度題明示輸入規模、操作成本、最壞／平均／攤銷口徑及資料分布假設；不可混用單次成本與總成本。
- 測試題說明預期行為與候選缺陷；選最有效測試時，提供足以排除其他選項的判準。反例必須真的違反主張。
- 修補題說明允許修改範圍、效能及相容性限制；不能靠改掉需求讓錯誤消失。
- 程式與縮排保持完整，避免過長或與考點無關的模板；若必需條件放不進長度限制，縮小問題。
- 使用現代語言的穩定特性；歷史語法僅在明示環境且具比較價值時出現，不靠品牌、套件版本或冷門 API 背誦增加難度。

## 與其他題庫的分工

以下交集是刻意保留的知識連結；依解題主能力決定歸科，不以故事或工具名稱判定。跨科混合題須有單一主考點；只是換名詞的同考點題不能跨題庫重複。

- 計算機系統：共用順序、資料結構與系統概念；本科以實作行為、演算法及正確性為主，計算機系統以資料表示、資源與架構為主。
- 資訊安全：一般程式錯誤歸本科；若主要判準是阻止攻擊或未授權存取，歸資安。看到程式碼不代表必須歸本科。
- 辦公軟體應用：儲存格公式與辦公功能歸辦公軟體應用；以巨集為背景的一般迴圈、抽象與演算法可歸本科。
- 人工智慧應用：一般資料轉換、API 程式正確性可歸本科；模型評估、檢索與 AI 專屬工作流程歸 人工智慧應用。
- 網際網路與通訊：通訊、路由與 HTTP 行為歸網路科；用 API 的程式邏輯可歸本科。
- 專案管理與數位素養與資訊倫理：軟體專案的交付治理、著作及專業倫理分屬兩科；本科不以技術故事包裝管理或道德選擇。

## 輸出與維護

遵守 ai-exam.md 的原創、JSON、繁體中文及輸出契約；difficulty 採 1～9 星規格，實際值與順序依後端分配表及可接受的 Schema，不擅自覆寫。題幹最多 600 字元、單項 300 字元、解析 1000 字元。中文用全形標點，程式、公式、單位及識別字保留正確語法；不依賴外部連結、圖片或附件作答。

維護者以採用語言的官方規格、標準函式庫文件與必要的演算法定義核實語意；出題時不自行讀檔或執行程式。

來源連結只供維護者核對，生成時不自行上網、讀檔、執行程式或使用工具。題數、難度抽樣與輸出契約見共通規則。
