# 資料庫

`database/schema.sql` 定義完整資料結構；`questions-seed.sql` 提供八科各 50 題、共 400 題已通過檢核的 AI 題目。

`node src/setup.js` 建立缺少的資料表，僅在首次建立題庫時匯入種子題目。重跑會保留帳號、題目、成績及作答；`--demo` 僅在帳號不存在時建立本機管理者。

| 資料表 | 用途 |
| --- | --- |
| user | 帳號、密碼雜湊、角色、登入時間與小數最高分 |
| questions | 題目版本、難度、解析、檢核狀態及統計欄位 |
| exam_records | 正式成績及依序保存的題目 ID／所選答案 |
| node_active_exams | 每個帳號唯一的進行中考卷，完成後只保留精簡結果 |
| node_exam_submissions | 交卷 nonce，避免重複入庫 |
| node_sessions | 登入狀態與一小時練習檢討 |

## 題目版本與作答

`questions.id` 是內容版本主鍵。`content_hash` 包含題庫、題幹、各字母對應的選項、答案、解析與難度。內容修改建立新 ID 並停用原版本；相同內容可重用既有版本。`approved` 供抽題，`pending` 待檢核，`rejected` 停用。停用保留內容，供歷史檢討及進行中考卷讀取。

正式與練習作答皆為：
```json
{"version":2,"questions":[{"question_id":123,"selected_answer":"A"},{"question_id":456,"selected_answer":null}]}
```

陣列順序即出題順序，未答為 `null`。正式紀錄另存交卷分數、開始／交卷時間及耗時。完整考卷只在準備與作答期間暫存。

## 計分與統計

分數＝答對題目的星等總和／全卷星等總和×100，四捨五入至兩位小數，滿分 100.00。分數欄位使用 `DECIMAL(5,2)`。歷史查詢以 JSON_TABLE 將作答連至題目，依難度即時計分。

正式交卷以同一交易寫入新題、成績與 `user.high_score`；最高分使用 GREATEST 更新，練習不更動最高分。

`appearance_count`、`correct_count`、`unanswered_count` 分別預留合法交卷後的出現、答對、未答次數，目前尚未接上累計邏輯，管理頁僅供查看。

檢討頁依現有統計即時計算浮動難度，不寫回題目的 difficulty。各初始星等的預期答對率由 1 星 90% 至 9 星 30%，每級遞減 7.5 個百分點；以 20 次先驗權重平滑，分別依上下剩餘空間正規化後乘以 0.99。有效作答次數為 appearance_count − unanswered_count，重複作答目前不另去重。浮動難度僅供檢討顯示，計分與抽題維持初始整數星等；統計尚未接上交卷累計，無有效樣本時維持初始難度。
